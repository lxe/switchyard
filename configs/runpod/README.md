# RunPod experiment configuration

`qwen-small.json` is the fleet definition for the live experiment. It pins three Qwen3.5 snapshots, a small Ubuntu image by digest, a separately hydrated vLLM runtime, engine arguments, allowed GPU types and regions, R2 archive prefixes, bootstrap agent checksum, and rental limits. The R2 account address and bucket identify the experiment's existing artifacts; access still requires credentials. Replace these fields to use your own storage.

`gauntlet.json` defines cold and hot single calls, a 1,000-call burst, comparisons with the reference policies, staggered arrivals, longer inputs, underestimated outputs, and dependent requests. Each case records its output estimate, hard output bound, arrival pattern, throughput target, and completion budget. Model output lengths remain unknown until generation finishes.

`smoke.json` is the first GPU boundary check: one cold call, one hot call, and a 32-call burst. Use it with `--model qwen3.5-0.8b` before the full experiment to verify the hydration recipe and streamed usage on one endpoint. It uses the fleet's rental and cleanup limits.

`prices-2026-10-10.json` preserves the initial catalog quote. Availability is a snapshot. Every execution queries the catalog again with the configured minimum CUDA version and records the eligible offers in its receipt directory. The configured disk rate is $0.10 per GB per month, converted using 730 hours per month. Rental receipts are estimates until reconciled with provider billing.

The 0.8B throughput and startup priors use the measured L40S smoke run in [the cache-reuse receipt](../../experiments/gpu-cache-reuse-l40s-0.8b.json). Its configured cache currently restricts that model to L40S offerings. The scheduler KV admission limit is 32 sequences × 4,096 context tokens, below the observed physical KV capacity. These values describe that model/runtime/engine configuration and short smoke corpus; they are estimates for new workloads, not guarantees. The 2B/4B priors and all prefill work factors remain unmeasured planning assumptions. The live reports measure end-to-end output throughput, streamed first-content latency, and actual token usage. Cold startup includes provider allocation, image preparation, hydration, engine initialization, and client transport.

Credentials are named by environment variables. Credential files, presigned storage URLs, agent tokens, ownership journals, downloaded tokenizers, and raw run artifacts stay outside Git. The source configuration and workload definitions are checked in; every run saves the configuration it actually used.

See [the live execution guide](../../docs/RUNPOD.md) for commands, recovery, and measurement limits.

`gauntlet-l40s-0.8b.json` is a bounded L40S run of all ten gauntlet cases (1,406 calls) using the prepared 0.8B cache. Its $0.60 cap and 900-second deadline apply to the complete run, including elastic capacity. It pins the telemetry agent and disables runtime retries. This serving configuration provides a scheduler baseline with prefix caching disabled; the separate engine comparison tests enabled prefix reuse.

`qwen-extents-l40s.json` pins all three published header-first Qwen weight layouts, the full CUDA 12.9 vLLM runtime, and the fixed RC2 agent. Runtime hydration streams to the host filesystem; model extents use RAM-backed positional writes and a bounded 16 MiB CUDA staging buffer. Its [control-plane preflight](../../experiments/qwen-extents-l40s-preflight.json) verified runtime/model manifests and tokenization for all three models without allocating a GPU. The current L40S quote is $1.09/hour plus $0.0109589/hour for the configured 80 GB disk; execution refreshes this quote.

This extent fleet is a preparation configuration until compatible compiler-cache references are attached. Legacy-model cache labels do not match the new content and loader identities, so those caches must be prepared again. Capacity priors carry conservative full-runtime comparison measurements; startup priors describe the older baseline, and the prefill work factor remains uncalibrated. They do not establish raw-extent startup performance. The full gauntlet retains all ten cases and 1,406 calls per model, with a $0.75 per-model and $2.25 overall execution cap. Runtime source patches remain disabled pending semantic and complete serving validation.
